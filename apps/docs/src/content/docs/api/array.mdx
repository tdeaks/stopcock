---
title: A (Array)
description: Filter, map, sort, group, and 30+ array functions for pipe
---

The array module has 128 dual operations. `A.fn(arr, ...)` runs direct
data-first, while `A.fn(...)(arr)` is the curried data-last form used by
`pipe(arr, A.fn(...))`. The [complete dual-call
catalogue](/api/modules#complete-dual-call-catalogue) lists every pair.
Streaming operators such as `map`, `filter`,
`flatMap`, `take`, `drop`, `takeWhile`, and `dropWhile` can be fused into a
single loop by the separate build-time [`@stopcock/fp-compiler`](/concepts/fusion)
plugin. Plain `pipe` at runtime never fuses on its own; it just calls each
step in order. Terminal folds, accessor terminals, and materializing
operations have different boundaries in what the compiler can fuse.

## Accessors

```ts
head<A>(arr: readonly A[]): Option<A>
last<A>(arr: readonly A[]): Option<A>
first<A>(arr: readonly A[]): Option<A> // alias for head
headOrUndefined<A>(arr: readonly A[]): A | undefined
lastOrUndefined<A>(arr: readonly A[]): A | undefined
headNonEmpty<A>(arr: readonly [A, ...A[]]): A
lastNonEmpty<A>(arr: readonly [A, ...A[]]): A
tail<A>(arr: readonly A[]): A[]           // all except first
init<A>(arr: readonly A[]): A[]           // all except last
length<A>(arr: readonly A[]): number
isEmpty<A>(arr: readonly A[]): boolean
```

`head`, `last`, `length`, and `isEmpty` are accessor terminals: the compiler
can treat them as the last step of a fused loop. Option-returning names are
the default; `*OrUndefined` is the explicit JavaScript interop escape hatch.

```ts
filter<A>(pred: (a: A) => boolean): (arr: readonly A[]) => A[]

filterWithIndex<A>(pred: (a: A, i: number) => boolean): (arr: readonly A[]) => A[]

scan<A, B>(f: (acc: B, a: A) => B, init: B): (arr: readonly A[]) => B[]

```

`map`, `mapWithIndex`, `filter`, `filterWithIndex`, and `flatMap` are the
streaming steps the compiler can fuse into one loop. `reduce` is a terminal
fold. `forEach` is a terminal side-effect traversal. `scan` returns an
intermediate array of every running value.

## Ordering

```ts
sort(arr: readonly number[]): number[]
sortBy<A>(arr: readonly A[], cmp: (a: A, b: A) => number): A[]
sortBy<A>(cmp: (a: A, b: A) => number): (arr: readonly A[]) => A[]
reverse<A>(arr: readonly A[]): A[]
```

Materialization boundaries: they need the whole array before they can
produce anything. `sort` and `sortBy` always run a full sort; a following
`take` does not get a bounded top-k shortcut.

## Examples

```ts
import { pipe } from '@stopcock/fp'
import * as A from '@stopcock/fp/array'

type Product = {
  name: string
  price: number
  category: string
  inStock: boolean
}

// the compiler can fuse filter -> map -> take into one loop;
// plain pipe just runs each step in order
const deals = pipe(
  products,
  A.filter((p: Product) => p.inStock && p.price < 50),
  A.map((p) => ({ name: p.name, price: p.price })),
  A.take(10),
)

// group + count
const byCategory = A.groupBy(products, (p: Product) => p.category)
// { electronics: [...], clothing: [...] }

// rolling total
A.scan([100, 200, 150, 300], (acc, x) => acc + x, 0)
// [0, 100, 300, 450, 750]

// remove duplicates by key
const uniqueCustomers = pipe(
  orders,
  A.uniqBy((o: { customerId: string }) => o.customerId),
)

// set operations
const newUsers = A.difference(allUsers, existingUsers)
const commonTags = pipe(tagsA, A.intersection(tagsB))

// batch processing
const batches = A.chunk(records, 100)
```
