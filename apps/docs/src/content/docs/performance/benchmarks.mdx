The table records the final 23 July 2026 local run on Darwin arm64 with Bun
1.3.14/JavaScriptCore and Node 24.18.0/V8 13.6. It reports raw minima even
where a pinned case documents semantic work or native-call overhead that
cannot be removed. Ratios from different contracts are not interchangeable
and should not be combined or compared with absolute throughput from another
machine.

Every gate writes raw and evaluated JSON and rejects provenance drift,
missing populations, skipped or incorrect semantics, undersampling, malformed
statistics, invalid confidence bounds, or missed floors. Above-ceiling
measurement error is accepted only when the gate recomputes the full paired
95% confidence interval and its lower bound still clears that case's floor.
The operation compiler lane balances both lexical sampler roles in fresh
workers and retains all four raw timing arrays. JavaScriptCore reduces
fixed-input `length` and `isEmpty` repetitions to counter-loop work, so those
two rows remain correctness and code-generation canaries rather than claimed
latency measurements.

CI runs the contracts with pinned Bun 1.3.14 and Node 22 on Linux x64 and
macOS arm64, retains all artifacts, and separately gates the shared runtime
chunk and published tarball size.

```bash
cd benchmarks
bun run perf:portable:bun
bun run perf:compiler:bun
bun run perf:iter:bun
bun run perf:hot-paths:bun
bun run perf:typed-array:bun
bun run perf:package-size
```

The normal `@stopcock/fp` runtime is strict-CSP compatible: it does not use
`eval`, `new Function`, function-source parsing, or a dynamically loaded JIT
chunk, and it does not require `unsafe-eval`. `@stopcock/fp-compiler` performs
optional specialization during the build; the compiler is not imported into
the emitted application's runtime graph.

## Pipeline fusion

### Fully fused: filter → map → take

```ts
pipe(
  data,
  A.filter((x) => x > threshold),
  A.map((x) => x * 2),
  A.take(10),
)
```

All three operations fuse into a single loop. `take(10)` halts after 10 results. The loop never visits the rest of the array.

<FusionSpotlight />

<TabbedScalingChart category="filter→map→take(10)" />

This shape can remain nearly flat as input grows because `take(10)` stops the
fused loop once ten matches are produced. Treat the chart as an exploratory
comparison, not a universal throughput claim: absolute rates depend on the
selected runtime and host, while the release gate above uses paired,
same-process ratios and correctness checks.

### Partial fusion: filter → map → sort → take

```ts
pipe(
  data,
  A.filter((x) => x > 0),
  A.map((x) => x * 2),
  A.sortBy((a, b) => a - b),
  A.take(5),
)
```

`sort` can't fuse because it needs the full array. `filter → map` fuses into one loop, materializes the result, then `sort` runs, then `take` slices.

<TabbedBarChart category="filter→map→sort→take(5)" arraySize={10000} />

<TabbedScalingChart category="filter→map→sort→take(5)" />

The advantage shrinks because `sort` dominates the runtime. But partial fusion still helps. The fused `filter → map` segment avoids an intermediate array and runs in one pass before handing off to `sort`.
