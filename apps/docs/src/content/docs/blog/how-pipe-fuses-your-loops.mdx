> Updated for `@stopcock/fp` 2.0. The old runtime-JIT design was removed.

Ordinary array chains allocate intermediate arrays:

```ts
const result = users
  .filter((user) => user.active)
  .map((user) => user.name)
  .slice(0, 10)
```

Stopcock operators carry small internal operation tags:

```ts
import { pipe } from '@stopcock/fp'
import * as A from '@stopcock/fp/array'

const result = pipe(
  users,
  A.filter((user) => user.active),
  A.map((user) => user.name),
  A.take(10),
)
```

The planner recognizes compatible tagged segments and dispatches to checked-in,
hand-shaped loop templates. A filter/map/take segment behaves roughly like:

```ts
const output = []
for (let index = 0; index < users.length; index++) {
  const user = users[index]
  if (!user.active) continue
  output.push(user.name)
  if (output.length === 10) break
}
```

There is no `eval`, `new Function`, function-source parsing, or dynamically
loaded JIT chunk in the public runtime graph. This keeps the same code valid
under strict CSP and across Node, Bun, Deno, browsers, workers, and edge
runtimes.

## Plan once for repeated work

For a hot pipeline used with many inputs, compile its shape once:

```ts
import { compile, explain } from '@stopcock/fp'

const activeNames = compile(
  A.filter((user: User) => user.active),
  A.map((user) => user.name),
  A.take(10),
)

activeNames(firstPage)
activeNames(secondPage)

console.log(
  explain(
    A.filter((user: User) => user.active),
    A.map((user) => user.name),
    A.take(10),
  ),
)
```

`compile` keeps normal callback semantics. `compilePure` is an explicit promise
that callbacks are pure and may enable additional rewrites. Purity is never
silently guessed from `Function#toString`.

## Boundaries

Item-by-item transforms such as map, filter, reject, filter-map, take, and drop
can share a streaming segment. Whole-input operations such as sorting,
reversing, grouping, and global deduplication form materialization boundaries.
Terminals such as reduce, count, sum, and short-circuit searches can finish a
segment without another intermediate collection.

Specialized optimizations are semantic, not magical. For example, a sorted
top-k request can select and sort only the required prefix when its ordering
contract allows that rewrite.

## Build-time lowering

`@stopcock/fp-compiler` is an optional build plugin for Vite/Rollup-compatible
hosts. It recognizes ordinary imports from `@stopcock/fp` and
`@stopcock/fp/array`, lowers supported call sites to direct loops, and emits
diagnostics for transformed or rejected shapes. It is a development dependency;
applications do not import it at runtime.

## When fusion helps

Measure your workload. Fusion is most useful for large inputs, early exit,
multiple compatible stages, and repeated hot paths. For a short collection or
a single native operation, clarity usually matters more than forcing a
compiled plan.

The benchmark suite measures source and packed-dist lanes on the real runtime
engine. Release gates compare the build compiler with a frozen loop emitter on
Linux x64 and macOS arm64 and reject correctness mismatches as well as
performance regressions.
